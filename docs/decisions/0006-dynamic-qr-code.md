# 0006 — Dynamic QR code via our own redirect

- Status: Accepted
- Date: 2026-11-08

## Context

We want a QR code to print now (posters, cards, merch) whose destination can change later:
today the site lives on a `vercel.app` address; the final domain isn't bought yet.

## Decision

The QR code encodes **`https://<project>.vercel.app/qr`**. The site redirects `/qr` with a
**temporary (307)** redirect defined in `next.config.ts`. To change where printed codes lead,
edit that one `destination` and push.

When the domain is bought: add it in Vercel and set the `vercel.app` domain to redirect to
it. Old QR codes then go `vercel.app/qr → domain/qr → destination`, and keep working.

## Alternatives considered

- **Paid "dynamic QR" services** — monthly fees; many disable codes when a trial or plan
  ends, breaking everything already printed.
- **Encoding the bare `vercel.app` URL** — works, but can't send scans anywhere other than
  the home page (e.g. a campaign page or member sign-up).

## Consequences

- The Vercel project must never be deleted or renamed, or printed codes break.
- The redirect must stay temporary; a permanent one gets cached by phones and browsers.
- Scans can be counted later (e.g. cookieless analytics on `/qr`) without reprinting.
- QR image files live in `brand/qr/`, generated by `npm run qr -- <url>` (`scripts/build-qr-code.mjs`).
